# 계획 작성과 재개

Oh My Pi v18.16.0의 `plan-mode-active.md`, `plan-mode-reference.md`에서 필요한 원칙을 선별·번역·수정했다. 원본 출처·해시는 harness 저장소의 `third_party/oh-my-pi/upstream.json`, 저작권 고지는 같은 폴더의 `LICENSE`에 보존한다. OMP 전용 URL·도구·승인 장치는 사용하지 않는다.

계획은 다음 세션의 에이전트가 실행할 수 있는 작업 명세다. 대화에서만 알 수 있는 중요한 선택을 남겨두지 않는다. 분량은 변경 규모에 맞춘다.

- 요청과 성공 기준을 쓰고, 조사한 실제 경로·동작에 근거를 둔다. 미확인은 표시한다.
- 구현 순서를 동작 단위로 쓰고, 재사용할 코드·바뀔 호출부·오류 동작을 명시한다.
- 검증은 구체적인 입력과 관찰할 결과로 쓴다. 빌드 성공만으로 새 동작을 입증하지 않는다.
- 사용자 결정, 허가된 작업, 작업 가정을 구분한다. 계획 저장 자체는 승인 행위가 아니다.
- 조사·구현으로 내용이 바뀌면 그때 계획을 갱신한다. 완료한 단계와 남은 단계가 구분되게 한다.
- 재개 시 현재 사용자 요청을 먼저 읽는다. 관련 있는 기존 계획만 이어가고, 새 요청을 낡은 계획으로 대체하지 않는다.
- 대화에서 계획 내용이 사라졌다면 `status`가 반환한 계획 파일을 다시 읽는다. 읽지 못하면 해당 경로와 오류를 확인하고 기억으로 내용을 만들어내지 않는다.

계획은 `plan --file 파일`로 프로젝트에 저장하고, 보고서 설계 절에서 연결한다. 계획 원문과 긴 실행 로그를 PM 보고서에 반복해서 붙이지 않는다.
