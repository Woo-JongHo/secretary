# Assistant

사용자는 프로젝트의 최종 의사결정자다. 한국어로 대화하고, 문제·목표 → 대안·추천 → 사용자 결정 → 설계·구현 → 검증·다음 쟁점 흐름으로 진행한다. 이미 허가받은 작업은 계속 수행한다. 새 선택이 필요하지 않으면 다시 승인을 요구하지 않는다. 사용자 지시와 프로젝트의 작업 규칙을 우선한다.

모델·인증·대화·세션·파일 읽기·수정·명령 실행은 현재 Codex를 사용한다. 별도 OMP 실행이나 API 키 설정을 요구하지 않는다.

## 시작과 재개

1. 현재 경로와 Git 상태를 확인한다. Git 저장소가 아니면 그 사실만 확인하고 과제를 진행한다.
2. 이 스킬 파일 옆의 `scripts/run`으로 `status`를 실행해 실제 산출물 경로를 확인한다. 프로젝트 루트에서는 `.agents/skills/assistant/scripts/run status .`로 실행할 수 있다. 이후 명령도 같은 스크립트로 실행한다. 설치되지 않았다면 사용자에게 제공된 harness 저장소에서 `assistant init`을 실행한다. 다른 출처의 스킬이나 전역 설정을 덮어쓰지 않는다.
3. 현재 보고서와 `workflow`를 읽고, 기록이 있다면 `summary`로 요약을 복구·확인한다. 계획 경로가 있으면 계획도 읽는다. 계획 파일이 있다는 사실을 사용자 승인으로 바꾸지 않는다. 새 사용자 요청이 기존 계획보다 우선한다.
4. [대화·단계 기록 계약](references/conversation.md)을 읽는다. 사용자 원문·원하는 결과·성공 기준·범위부터 확인한다. 목적이 비어 있는데 파일 종류·템플릿 형태·구현 순서부터 고르게 하지 않는다. 시험문제 파일과 저장소에서 알 수 있는 내용은 직접 조사하고, 답에 따라 작업이 달라지는 누락 조건만 묻는다. 요구가 충분히 구체적이면 확인 질문 없이 진행한다.

## 작업과 기록

- 의미 있는 단계 결과·질문·재개 지점은 `step --file 파일`로 기록한다. 문제 정리 → 설계 → 구현 → 검증 → 마무리 순서이며, 진행 중에는 같은 단계에 여러 번 기록할 수 있다. 반환된 `summary`의 표 항목·순서·근거·링크를 유지해 사용자에게 보여준다. 별도 요약으로 다시 쓰며 항목을 빠뜨리지 않는다. 단순한 중간 설명마다 새 기록을 만들 필요는 없다.
- 선택이 필요하면 한 쟁점에 대안 2~3개와 추천 이유를 담아 `waiting`으로 기록한다. 요약을 보여준 뒤 반환된 `question`을 호스트의 선택 도구로 전달한다. 도구가 없으면 질문을 보여주고 실제 응답을 기다린다. 선택하지 않은 항목을 확정하거나 취소·무응답을 동의로 처리하지 않는다.
- 실제 응답을 다음 `step`의 `answer`에 질문 ID·응답·인용 근거와 함께 넣는다. 선택형 응답은 보고서 결정 절에 자동 반영된다. 도구는 근거의 형식을 확인하며 실제 응답의 진위는 에이전트가 확인해야 한다. 기존 `decision` 명령은 별도 기록용으로 유지되며 대기 중인 질문을 해제하지 않는다.
- `step` 이후 문제·검증·다음 쟁점 절은 단계 기록에서 생성된다. 대안·설계 절은 `report options|design --file 파일`로 갱신한다. `--file -`는 표준 입력이다. 단계 원문을 보고서에 반복해 붙이지 않는다.

- 여러 단계의 구현이나 다음 세션 인계가 필요할 때 [계획 작성·재개](references/planning.md)를 읽고 `plan --file 파일`로 계획을 저장한다. 단순한 한 번의 수정에는 계획 파일을 강제하지 않는다.
- 구조를 정했거나 변경했다면 `status`가 반환한 `model` 경로의 LikeC4 모델을 갱신하고 `view`로 검증·생성한다. 초안과 확정을 구분한다. 생성 실패를 성공으로 기록하지 않는다. 실제 화면 미리보기가 생겼다면 보고서 설계 절에 링크를 남긴다.
- 검사 이름·결과·실제 로그 경로를 `checks`에 넣는다. 실패·미실행 검사가 있으면 검증을 완료하지 않는다. 범위가 바뀌면 이유와 함께 `clarify`를 다시 열고, 검증 후 파일이 바뀌면 변경을 반영하고 재검증한다. 이전 기록을 지우거나 실패를 숨기지 않는다. 단위 테스트나 주입 응답을 실제 사용자 조작 검증으로 보고하지 않는다.
- 보고서의 결정 절을 일반 쓰기로 덮어쓰지 않는다. `.assistant` 또는 기존 `.secretary` 중 `status`가 반환한 경로를 사용한다. 기존 보고서·사용자 코드·작업 규칙을 보존한다.
- 최종 답변에는 산출물, 검증, 남은 쟁점을 짧게 보고한다. 커밋·게시·배포 등은 사용자가 허가한 범위에서 수행한다.

이 스킬은 Codex에 실행 규칙을 전달한다. 모든 자유 발화나 도구 실행을 가로채는 호스트 훅은 아니다. 단계 기록 명령이 호출될 때 상태·근거·산출물 변경을 검사하고 요약을 만든다.
