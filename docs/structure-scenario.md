# 구조 완성 과제의 예상 대화

아래는 현재 Assistant에 “이 프로젝트의 구조를 완성해줘”를 입력한 **가상 시나리오**다. 예시 사용자 응답이나 검사 결과를 실제 결정·검증으로 기록하지 않는다. 현재 구현의 위치는 `source-map.md`에 있다.

## 1. 시작·조사

사용자: `$assistant 이 프로젝트의 구조를 완성해줘.`

Assistant: 현재 위치·Git 상태·보고서·단계·계획을 읽고 실제 실행 경로를 조사한다. 기존 Codex 사용과 핵심 선별 이식은 이미 정한 조건이므로 다시 고르게 하지 않는다.

Assistant: “실행·계획·보고서·단계 기록 모듈이 있습니다. 먼저 ‘완성’의 범위를 확인하겠습니다. 이후 과제를 바로 수행할 수 있는 동작 연결을 추천합니다.”

선택 도구의 한 쟁점:

- 새 과제 시작부터 질문·구현·검증·재개까지 연결 (추천)
- 폴더와 모듈 책임 정리까지
- 설치·시작 자동화까지

이 질문은 `clarify / waiting`으로 저장한다. 답이 없으면 구현하지 않는다. 아래 예시에서만 사용자가 첫 항목을 골랐다고 가정한다.

## 2. 의도·성공 기준

가상 사용자: “새 과제를 받아서 끝내고, 다음 세션에서도 이어갈 수 있는 구조.”

Assistant는 사용자 문장에서 다음 기준을 도출하고 조사 결과와 대조한다. 새 판단이 필요한 빈칸만 후속 질문으로 확인한다.

- 기존 Codex에서 과제를 시작한다.
- 중요한 선택은 실제 응답과 근거가 남는다.
- 단계별 요약·보고서·계획·View가 같은 과제를 가리킨다.
- 실패나 변경을 숨기지 않고 중단·재검증·재개한다.
- 새 프로젝트에서 실행한 검사로 연결을 확인한다.

원래 요청·목표·응답 근거·성공 기준·범위가 채워지면 문제 정리를 완료하고 설계로 넘어간다. 제한시간이나 제출 형식이 결과를 바꾼다면 그때 한 쟁점으로 묻는다.

## 3. 설계·View

Assistant: “진입·스킬 설치는 `cli/install`, 계획은 `plan`, 입력·요약 계약은 `conversation`, 단계·재개는 `stages`, 보고서 연결은 `session/project`가 맡도록 정리합니다.”

코드와 책임을 대조해 설계·실행 계획·LikeC4 모델을 갱신한다. 새로운 사용자 결정이 없으면 이미 허가된 설계를 진행하며 매 파일마다 진행 승인을 묻지 않는다. 호환성이나 범위에 영향을 주는 새 대안이 나타나면 그 쟁점만 묻는다.

단계 끝에는 같은 형식의 요약을 보여준다. 다음 표의 내용은 가상 예시다.

| 구분 | 이번 단계의 내용 |
| --- | --- |
| 확인된 것 | 사용자 목표와 모듈별 실행 경로를 대조했다. |
| 작업 가정 | 시험 환경의 Codex 실행·인증은 준비되어 있다. |
| 미확인·남은 쟁점 | 실제 시험문제의 제한시간·제출조건 |
| 검증 | 설계 모델 문법 검사 결과와 실제 로그 경로 |
| 산출물 | 설계·계획·아키텍처 모델·View |

요약 아래에는 다음 행동·현재 상태·보고서·View·단계 원문 링크가 붙는다. 설계 초안이 사용자 확정을 받은 것처럼 바뀌지 않는다.

## 4. 구현

Assistant는 확정된 성공 기준과 현재 코드의 차이를 채운다. 파일을 만든 사실만으로 완료하지 않고 호출부·실패 동작·복구까지 연결한다. 의미 있는 구현 단위가 끝나면 실제 파일을 등록하고 같은 형식으로 요약한다. 기존 사용자 코드와 결정은 보존한다.

## 5. 검증·수정

타입·단위 검사, 설치된 실행 스크립트, 새 프로젝트의 시작·질문·단계·재개, 실제 LikeC4 빌드, Codex의 명령 수용을 범위에 맞게 확인한다. 주입 응답 검사와 실제 사용자 UI 검증은 구분한다. GLM 독립 리뷰가 요청된 과제에서는 읽기 전용 리뷰를 받고 지적을 수정·재검증한다.

실패가 있으면 `verify`에서 원인과 다음 조치를 남긴다. 모두 통과하기 전에는 마무리로 넘어가지 않는다. 검증 후 파일이 바뀌면 낡은 성공으로 닫지 않고 관련 단계를 다시 열어 검증한다. View 모델만 바뀐 경우에도 오래됨을 표시하고 다시 생성한다.

## 6. 마무리·재개

Assistant는 바뀐 동작·실제 검사와 로그·남은 한계·다음 행동을 보여준다. 현재 소스와 검증·View가 일치하면 마무리를 완료한다. 커밋·푸시는 별도 허가 범위에 따른다.

다음 세션의 사용자: `$assistant 이어서 하자.`

Assistant는 현재 위치·Git 상태부터 다시 확인하고 원문 기록에서 마지막 단계와 질문·검사·산출물 변경을 복원한다. 대기 중이면 그 쟁점부터, 검증이 낡았으면 재검증부터 이어간다. 사용자가 목표를 바꾸면 이전 완료를 보존한 채 문제 정리를 다시 연다.
